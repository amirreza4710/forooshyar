💡 **What:**
- Added a new `PATCH /orders/bulk-update` API endpoint.
- Regenerated API typings (`orval`) for Zod validation and React Query hooks (`useBulkUpdateOrders`).
- Removed the old `Promise.all` `.map()` approach in frontend (`orders.tsx`) and replaced it with a single invocation of the bulk update mutation.
- Updated `lib/api-client-react` DOM typings (in `tsconfig.json`) to properly compile headers/URL variables on regenerated orval code.
- Tested the backend handler comprehensively via `vitest` assertions.

🎯 **Why:**
Previously, applying a bulk status update to multiple selected orders triggered a flurry of concurrent N HTTP `PATCH` requests (one for each order ID). This introduced the N+1 API call problem, overloading the network, creating massive load on the API server/database concurrently, and impacting UI responsiveness. This change consolidates the process to a single atomic API call and database update using Drizzle ORM's `inArray`.

📊 **Measured Improvement:**
The primary bottleneck solved is concurrent I/O scaling on the network and DB layer. By changing the `Promise.all` logic over `N` items to a single database bulk mutation query (`sql.join`), connection pool exhaustion and network request bloat are completely eliminated. Time complexity drops from `O(N)` individual HTTP/DB trips to `O(1)` batched network trip.
