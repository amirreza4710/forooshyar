# ADR-008: Event-Informed and Ledger-Based Billing

## Status

Accepted

## Context

Future billing must support Billable Seats, metered AI, API and communication services, contract versions, tenant allowances, and reconciliation. Reading invoice amounts directly from user tables or raw event streams would be difficult to audit and unsafe under retries or late-arriving events.

## Decision

Use this target billing flow:

Domain Event → Metering Ingestion → Normalized Billable Event → Immutable Usage Ledger → Rating → Invoice Draft → Reconciliation → Invoice Issued

Required principles:

- Billable usage is derived from an immutable usage ledger.
- Raw domain events are normalized before rating.
- Idempotency is mandatory.
- Rating may read versioned Subscription, PriceBook, Contract, and Entitlement data.
- Invoice issuance follows reconciliation.
- Every billable event includes event_id, idempotency_key, tenant_id, event_type, occurred_at, received_at, source, schema_version, quantity, and unit.
- Event schemas are versioned.
- The 30-day MVP uses manual invoices and auditable usage exports.

## Consequences

### Positive

- Supports replay, reconciliation, late events, and dispute investigation.
- Decouples operational roles from billing.
- Creates a stable foundation for metered services and partner-aware contracts.

### Trade-offs

- Requires a future metering and ledger subsystem.
- Event schema governance becomes mandatory.
- Eventual automation is more deliberate than direct table-based billing.

## Deferred Implementation

This ADR does not authorize a Message Broker, automated Billing Engine, automated invoicing, Subscription Management, Partner Portal, or automated payouts in the MVP.
