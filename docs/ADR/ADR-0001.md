## 1. Context

در طول مرحله طراحی، دو مجموعه سند در مورد پشته فناوری پروژه وجود دارد:

1. **مستندات طراحی (`Markdown/PDF`)** — که بر اساس آنها معماری دامنه، bounded contexts و قواعد کسب‌وکار تعریف شده است. این اسناد در نسخه اصلی به پشته‌ای مبتنی بر `FastAPI + SQLAlchemy + Pydantic` اشاره داشتند.
2. **کدبیس جاری در مخزن** — که بر پایه `Express 5 + JWT + Pino` و `PostgreSQL + Drizzle ORM` و فرانت‌اند `React 19 + Vite 7 + TS + Tailwind 4 + shadcn/ui` ساخته شده است. این کدبیس هم‌اکنون معیارهای Sprint 0 را (از نظر Backend) پاس کرده است.

این اختلاف عمداً پنهان نشده، ولی تا زمانی که به‌صورت رسمی و مکتوب حل نشود، هر توسعه‌ی بعدی در انتخاب تکنولوژی و قراردادها با ابهام مواجه خواهد شد.

**نکته تکمیلی درباره تصمیم‌های این گپ:**
- کاربر تصمیم‌های صریحی برای محدوده MVP و مدل دامنه داده است (ثبت سفارش/مشتری/ویزیتور/پورسانت به‌عنوان اولویت، تفکیک CustomerProfile/Location/Contact/CreditProfile، ویزیتور به‌عنوان User، پورسانت بر پایه target/performance + order value، approval supervisor→admin، Rule Engine با seed + UI).
- هدف این تصمیم، تعیین تکلیف **مرجع استک و مرجعیت سندها** است تا این تصمیم‌ها پشت یک مرجع قاطع پیاده‌سازی شوند.
- مخزن به‌صورت **چند ارگانی** باید ساختار یابد، اگرچه پیاده‌سازی MVP از یک شرکت (قند خراسان) شروع می‌شود (به بخش تصمیم مراجعه کنید).

**شرط تعریف‌شده:** پیاده‌سازی باید روی **کدبیس فعلی** انجام شود تا از تکرار کار و گسست با پروژه جلوگیری شود.

## 2. Decision We Are Taking

ما به‌طور صریح و مکتوب موارد زیر را ثبت می‌کنیم:

### 2.1 مرجعیت (Source of Truth)
- **حاکمیت، معماری دامنه و قواعد کسب‌وکار** ← از **مستندات طراحی (`Markdown`)** می‌آید (Business Constitution, Master Specification, MVP Scope, Checkpoint، و Decision Records).
- **پشته فنی اجرایی، قراردادهای کد و پیاده‌سازی** ← از **کدبیس فعلی مخزن** می‌آید.
- به این معنا که **"علت محصول" از Markdown و "چگونگی اجرا" از کدبیس** حاصل می‌شود.

### 2.2 تکنولوژی اجرایی نهایی (عرصه توافق)
- **Backend:** `Express 5 + JWT + Pino`
- **API Contract:** OpenAPI (`openapi.yaml`) → Orval → React Query + Zod
- **Database/ORM:** PostgreSQL + Drizzle ORM
- **Frontend:** React 19 + Vite 7 + TypeScript + Tailwind 4 + shadcn/ui
- **Monorepo:** pnpm workspaces
- **نکته:** هر اشاره‌ی قدیمی به `FastAPI/SQLAlchemy/Pydantic` در مستندات اولیه، **به‌عنوان سابقه طراحی تاریخی** ثبت می‌شود و دیگر مرجع پیاده‌سازی نیست (مگر تصمیم معماری جداگانه‌ای گرفته شود).

### 2.3 مرجع دامنه و قواعد
- مدل دامنه و قواعد (بسته‌های دامنه، KPI، Rule Engine، پورسانت، اعتبار، Soft Delete، Audit Trail، تفکیک امتیاز اعتباری از پورسانت ریالی) **از Markdown مرجع می‌آیند** و در لایه‌ی کد با قراردادهای repo پیاده‌سازی می‌شوند.

### 2.4 Multitenancy
- MVP از **یک شرکت (قند خراسان)** شروع می‌شود.
- با این وجود، **زیرساخت دخیره‌سازی باید از ابتدا چندارگانی در نظر گرفته شود** (فیلد `organization_id` / جدول `organizations` و پیشوند بر اساس آن در جداول حساس)، تا با کم‌ترین هزینه مهاجرت، شرکت/پایلوت دوم (نادران‌گستر) موفق شود.
- این صرفاً «قابلیت» نیست؛ **الزام معماری است**.

## 3. Consequences

### 3.1 Experience (مزایا)
- ✅ رفع کامل ابهام استک برای هر توسعه‌ی آینده.
- ✅ یک منبع مرجع واحد برای هر دو جنبه (دامنه و اجرا) وجود خواهد داشت.
- ✅ توسعه‌ی روی کدبیس جاری بدون بازنویسی، ادامه پیدا می‌کند.
- ✅ صرفه‌جویی در زمان و جلوگیری از تکرار کار تکراری.

### 3.2 الزامات بعدی (Costs & Obligations)
- 📌 تمام مستندات قدیمی که `FastAPI` را مرجع اجرا می‌دانستند، باید **برچسب تاریخچه/تصمیم قدیمی** بگیرند.
- 📌 قواعد دامنه که باید از Markdown به کد منتقل شوند، باید یک‌به‌یک **با Decision Record یا Master Specification** مرتبط و track شوند تا از گسست جلوگیری شود.
- 📌 نیاز به **review** این ADR توسط ذینفعان و سپس commit در بخش تصمیم‌های پذیرفته‌شده.
- 📌 اگر بعداً تصمیم معماری دیگری (مثلاً ادغام/جایگزینی stack) گرفته شود، باید به‌عنوان یک **ADR جدید** ثبت شود، نه تغییر در این سند.

---

## 4. Next Steps

1. **ثبت سند** در ساختار تصمیم‌های پذیرفته‌شده (مطابق convention repo).
2. **برچسب‌گذاری** مستندات قدیمی `FastAPI` به‌عنوان تاریخچه/قدیمی.
3. **تضمین وجود** `organization_id` در تمام جداول حساس (در صورت نبود، در schema مهاجرت اضافه شود).
4. **شروع پیاده‌سازی** MVP بر اساس اولویت‌های مصوب (Order → Customer/Visitor → Commission) روی کدبیس جاری.
